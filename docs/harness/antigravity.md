# ZenSpec on Google Antigravity

Researched 2026-09-24 from the official docs at antigravity.google. Items marked **(unverified)** are inferred or undocumented and haven't been tested in a live Antigravity session.

## What Antigravity supports

| Extension point         | Support                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Where                                                                                                                                                                                        |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Skills**              | Yes. A `SKILL.md` with `name` (optional) and `description` (required) frontmatter. The agent sees name and description, then reads the body when relevant (progressive disclosure). Also invocable as `/<skill-name>`.                                                                                                                                                                                                                                                                                    | Workspace `.agents/skills/<name>/`. Global `~/.gemini/config/skills/<name>/` (IDE, 2.0) or `~/.gemini/antigravity-cli/skills/<name>/` (CLI). [docs](https://antigravity.google/docs/skills/) |
| **Rules**               | Yes. `AGENTS.md` / `GEMINI.md` (plain Markdown), or modular `.md` files with `trigger: always_on \| model_decision \| glob \| manual` frontmatter. 24 KB per file; `always_on` rules share a 20k-token budget.                                                                                                                                                                                                                                                                                            | `.agents/rules/*.md`, `~/.gemini/config/rules/*.md`. [docs](https://antigravity.google/docs/rules)                                                                                           |
| **Workflows**           | Yes (`/workflow-name`, 12,000 characters max), but **deprecated in favor of skills by 2026-11-01**. Not worth targeting.                                                                                                                                                                                                                                                                                                                                                                                  | [docs](https://antigravity.google/docs/ide/workflows/)                                                                                                                                       |
| **Hooks**               | Yes: `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`. Commands get JSON on stdin (`toolCall.name`, `toolCall.args`, `workspacePaths`, …). `PreToolUse` returns `{"decision": "allow"\|"deny"\|"ask"\|…, "reason": "…"}`. `PostToolUse` returns `{}` and **can't inject context**. `Pre/PostInvocation` can return `{"injectSteps": [{"ephemeralMessage": "…"}]}`. Default timeout is 30 s. File-edit tools: `write_to_file`, `replace_file_content`, `multi_replace_file_content`. | `.agents/hooks.json`, `~/.gemini/config/hooks.json`, or a plugin's `hooks.json`. [docs](https://antigravity.google/docs/hooks/)                                                              |
| **MCP**                 | Yes. `mcp_config.json` with `mcpServers` (stdio `command`/`args`, or remote `serverUrl`). ZenSpec v2 has no MCP server, by design (plan §3).                                                                                                                                                                                                                                                                                                                                                              | `.agents/mcp_config.json`, `~/.gemini/config/mcp_config.json`. [docs](https://antigravity.google/docs/mcp/)                                                                                  |
| **Plugins**             | Yes. A directory with `plugin.json` (`name` required) plus optional `skills/`, `rules/`, `agents/`, `hooks.json`, `mcp_config.json`. Install with `agy plugin install <path>` or place it in `.agents/plugins/` or `~/.gemini/config/plugins/`. Works in both the IDE and the CLI.                                                                                                                                                                                                                        | [docs](https://antigravity.google/docs/plugins/)                                                                                                                                             |
| **Background commands** | The agent runs terminal commands and can leave long-running ones in the background. **(unverified)**: the docs we read don't say whether a finished background command wakes the agent the way Claude Code's background Bash does. Use `zenspec review --wait 10m` and re-run the printed `next:` command as the fallback (plan §8.4).                                                                                                                                                                    |                                                                                                                                                                                              |

## Recommended integration

`plugins/antigravity/` is an Antigravity plugin:

- `plugin.json`: the manifest.
- `skills/zenspec/SKILL.md`: the same skill as Claude Code (kept identical by a test).
- `rules/zenspec.md`: a 3-line `always_on` rule (about 60 tokens) that states the approval gate, so it holds even when the skill isn't loaded.
- `hooks.example.json`: an **opt-in, experimental** gate and comment delivery. It reuses `plugins/claude-code/hooks/zenspec-hook.mjs` in its `antigravity-pre` and `antigravity-invocation` modes.

Install:

```bash
npm install -g zenspec
agy plugin install "$(npm root -g)/zenspec/plugins/antigravity"
# or copy that folder to .agents/plugins/zenspec (workspace) or ~/.gemini/config/plugins/zenspec
```

To enable the hooks, copy `hooks.example.json` to `hooks.json` in the installed plugin (or to `.agents/hooks.json`), and replace `<ZENSPEC_DIR>` with the output of `echo "$(npm root -g)/zenspec"`. The hook fails open and stays silent unless it blocks or has comments to deliver, like the Claude Code one.

## Uncertain points (verify before relying on the hooks)

1. **The edit tools' path argument name isn't documented.** The script looks for `TargetFile`, `targetFile`, `file_path`, `filePath` and `path` in `toolCall.args`. If none matches, the edit is allowed (fail open).
2. **`decision` is documented as required** in `PreToolUse` output. The script prints nothing when it allows an edit, because returning `"allow"` would auto-approve and skip the user's own permission prompts. Whether empty output means "no opinion" is **(unverified)**.
3. **No plugin-root variable** is documented for hook commands, hence the absolute-path placeholder.
4. **`PostInvocation` + `injectSteps`** is how implementation-time comments get delivered. The `ephemeralMessage` step type comes from the docs, but its exact visibility to the model is **(unverified)**.
5. Without the hooks, the baseline is the skill, the rule and the CLI, and reviewer comments made during implementation arrive at the final `zenspec review <file> -m "implemented"` (plan §10).
